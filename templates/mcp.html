🔌 MCP 接入指南

把本站每日论文数据接入你的 AI 编程助手（Cursor / Claude Code / Codex），让 AI 直接读取论文、精读解读和全文。

这是什么？

本站实现了 Model Context Protocol (MCP) 服务端。接入后，你的 AI 终端工具就能像调用函数一样查询本站论文数据——例如「帮我看看今天有哪些 🔥 必读论文」「找一下 XXX 作者最近的工作」「读一下 2402.12345 的精读解读」。

端点地址

所有工具的接入地址都一样：

{{ mcp_endpoint }}

提示：如果你通过内网/局域网访问，请把上面的域名换成你实际能访问的地址。

⚠️ 这个地址是给 AI 工具（POST 请求）用的，不是给人用浏览器打开的。直接在浏览器访问会看到 405 Method Not Allowed，这是正常的——说明端点在线。本说明页（你正在看的）的地址是 /mcp-guide。

📋 提供的工具

接入后，AI 会自动看到以下工具（全部只读，不会改动你的任何数据）：

📄 论文内容

list_dates

列出所有可用日期（倒序）。了解有哪些数据。

list_papers

列出某天的全部论文（标题/作者/评分/推荐等级/领域）。传 include_analysis=true 可一次性带上全部精读解读，让 AI 直接按内容筛选。

get_paper

取单篇论文完整信息：元数据 + LLM 精读解读全文。最常用。

search_papers

跨所有日期按关键词搜索（标题/作者/分类码/id）。

get_paper_fulltext

取 PDF 提取的全文（首次较慢，按需用）。

💬 社区互动（只读）

get_interactions

某天所有论文的 👍点赞 / 👎踩 / 💬评论数（按热度排序）。看哪些论文被讨论。

get_comments

取某篇（或某天全部）论文的评论。含评论者、内容、时间。

get_community_highlights

某篇论文的社区标注聚合（去重、匿名）——大家都标了哪些关键句。

get_site_stats

站点访问统计：今日/累计访问量、活跃用户、最近 N 天趋势。

1️⃣ Cursor

Cursor 通过 mcp.json 配置文件接入。二选一：

编辑配置文件（全局：~/.cursor/mcp.json；项目级：.cursor/mcp.json）：

{
  "mcpServers": {
    "arxivwatcher": {
      "url": "{{ mcp_endpoint }}"
    }
  }
}

保存后重启 Cursor。进入 Settings → Tools & MCP 可看到 arxivwatcher 已连接。

在 Cursor 中：Settings → Tools & MCP → + Add new MCP Server

  • Type: streamableHttp
  • Name: arxivwatcher
  • URL: {{ mcp_endpoint }}

本站 MCP 端点公开无需鉴权，Headers 留空即可。

2️⃣ Claude Code

用命令行添加（推荐），或手动写 JSON 配置：

在终端运行：

claude mcp add --transport http arxivwatcher {{ mcp_endpoint }}

作用域默认 local（仅当前项目）。全局可用加 --scope user。

claude mcp add --transport http --scope user arxivwatcher {{ mcp_endpoint }}

验证：运行 claude mcp list，应看到 arxivwatcher。

编辑 ~/.claude.json（或项目根 .mcp.json）：

{
  "mcpServers": {
    "arxivwatcher": {
      "type": "http",
      "url": "{{ mcp_endpoint }}"
    }
  }
}

注意：Claude Code 用 "type": "http"（不是 streamable-http）。

3️⃣ Codex (OpenAI CLI)

Codex 用 TOML 配置文件 ~/.codex/config.toml（或项目级 .codex/config.toml）：

编辑 ~/.codex/config.toml，加入：

[mcp_servers.arxivwatcher]
url = "{{ mcp_endpoint }}"
enabled = true

本站无需鉴权，因此不需要 bearer_token_env_var。

在终端运行：

codex mcp add arxivwatcher --url {{ mcp_endpoint }}

启动 Codex 后运行 /mcp 验证连接。

✅ 验证

接入后，在任一工具里试着对 AI 说：

  • 「列出最近的论文日期」
  • 「看一下 2026-06-18 有哪些 🔥 必读论文」
  • 「把 2026-06-18 的论文连同精读解读一起读一遍，帮我挑出和语音分离相关的」（AI 会用 list_papers + include_analysis=true）
  • 「读一下论文 2402.12345 的精读解读」（需替换为真实 id）
  • 「搜索作者 Zhang 最近发表的论文」
  • 「2026-06-18 哪些论文被讨论得最多？」（get_interactions）
  • 「看看论文 2402.12345 大家都评论了什么」（get_comments）
  • 「这个站最近访问量怎么样？」（get_site_stats）

AI 会自动调用上面的工具并把结果总结给你。

❓ 常见问题

数据会经过服务器外的第三方吗？

不会。MCP 端点直接由本站提供，工具调用的请求/响应都在你和本站之间。AI 工具会把返回的论文内容作为上下文送给它配置的 LLM（如 Claude/GPT），这部分由你使用的工具决定。

连接失败 / 工具不显示？
  • 确认端点 URL 在你的网络可达（内网部署需用内网地址）。
  • Claude Code 用 type: http，Cursor 直接用 url，Codex 用 TOML 的 [mcp_servers.xxx]。
  • 改完配置记得重启对应工具。
支持流式输出吗？

本端点遵循 MCP Streamable HTTP 规范，POST 返回标准 JSON-RPC 响应。由于工具都是即时只读查询，未启用 SSE 长流；这对所有三个客户端完全兼容。
